## Problem Statement

Task 1's benchmark exists entirely as a plan. Every hard-to-reverse call has been made and recorded — the arms, the metric set, the mask geometry, the table shape, the twelve registered rules — but nothing in the repository computes a number. A build session that sat down today would have to reconstruct the whole pipeline from a 1,748-line memo and thirteen resolved tickets, and every reconstruction detail it got wrong would be invisible: an encoder fed the wrong normalization returns a plausible tensor and raises nothing, a `pos_embed` loaded with the wrong axis order trains fine, a head that learns nothing scores exactly A1.

Worse, the value of the pre-registration decays the moment a number exists. C1–C4 and the twelve rules in ADR-0013 are only worth anything while they are ahead of the results; a rule discovered to be ambiguous *after* the first table is printed cannot be resolved honestly, because every available resolution now has a known consequence.

And the plan itself already carries one such ambiguity into the build, plus a stale arithmetic line it flagged and did not fix. Both need settling before the first arm runs, not after.

## Solution

A `benchmark/` package with **one shipping command**, `python -m benchmark.launch`, carrying three verbs:

```bash
uv run python -m benchmark.launch freeze              # write every committed input
uv run python -m benchmark.launch run --arm A4-R5 --size 20k --seed 0
uv run python -m benchmark.launch report              # the printed table, the C4 block, three figures
```

`freeze` writes the tile lists, the eval mask list, the train mask bank, `extractor_spec.json` and `task1-prereg-bar.json`, and is CPU-only. *(Amended 2026-08-13 — [#153](https://github.com/JStoschek/DEMAE/issues/153): it is no longer **local**. §3.3's real-void family needs #127's 24 granules on disk and reads one GLO-30 COG per source cell to assign the band each void is transplanted under — the band cannot come from SRTM, which by definition never observed the ground under a void, and #126 is what inferring it from the surround cost. A box without the granules is refused rather than committing a well-formed eval mask list with no real family in it.)* `run` executes exactly one (arm, size, seed) cell and appends its rows to the results parquet, having asserted the extractor contract, the registered bar and the split containment on the way in. `report` reads the parquet and renders the 396-number printed table, the 66-cell C4 rank block and the three figures, printing nothing that R5 does not permit it to print.

Determinism is the corpus's contract, one level up: two runs from the committed inputs reproduce the tables. Nothing that reaches the page is drawn at run time.

The deliverable is the benchmark plus its answers — the results memo in `docs/research/` answering C1, C2 and C3 in numbers and C4 in ranks, opening on §0's incomparability paragraph and carrying §6's fairness checklist verbatim.

## Implementation Decisions

**Package shape and the one entry point.** A new `src/benchmark/` package, torch-optional in the same way `src/dataset` is: the freeze and scoring paths import no torch, so the artifacts and A1 can be built on a box with no CUDA stack. `python -m benchmark.launch` is the only command that trains, scores or reports — ADR-0009's rule carried into Phase 2, for the reason it was written: *a seam that nobody is on both sides of is a feature that does not exist*. Three verbs, `freeze`, `run` and `report`. `benchmark.train` and any per-stage `main` that appears during the build are documented as not a way to produce a result, exactly as `pretrain.train` is.

Modules, roughly one per plan section, each importable and none of them a second command:

- `benchmark.config` — the frozen run object, `pretrain.config.RunConfig`'s sibling: every knob from §4 at its cited default, round-tripping to a partial dict, hashing to a **config hash** that covers the recipe and not the environment paths. An arm is this object with a knob moved.
- `benchmark.tiles` — the four tile-list draws and the split-containment assertion.
- `benchmark.masks` — the mask generator (blob, rectangle, real transplant), the RLE codec, the eval mask list and the train mask bank. Promoted from `prototypes/p119_fill_headroom_proto.py`'s generator and `prototypes/p121_{masks,bank}.py`, which are the code the measured constraint checks were run against.
- `benchmark.voids` — real SRTM void extraction, the `num > 10 AND num < 201` predicate with its documented strict flag, component labelling, the size sub-rows, and GLO-30-sourced band assignment. Promoted from `prototypes/p135_void_ruggedness_proto.py` and `scripts/p127_fetch_srtm_voids.py`.
- `benchmark.extract` — ADR-0012's contract: the extractor, the `extractor_spec.json` writer, and the loader that re-checks and refuses.
- `benchmark.head` — the shared conv head for A4/A5/A6, its §4.1 loss, and §2.4's residual rule.
- `benchmark.train` — the head-training pass: the committed bank in, one trained head out. Named in this section's own "not a way to produce a result" sentence before it existed; added to this list in flight ([#159](https://github.com/JStoschek/DEMAE/issues/159)), because a module that is documented and not enumerated is one a reader has to find.
- `benchmark.tune` — §4.1's **one** hyperparameter search, on A6, over val, and the guard that keeps it to one. Not anticipated by this list, and it is a module rather than a stretch of `train` for the reason the section gives about the head itself: *tuned once, then frozen for every arm* is a pre-registration-shaped claim, and the mechanism that enforces it — a frozen recipe object every arm loads, and a refusal for any cell that has drifted from it — is a thing with a name ([#159](https://github.com/JStoschek/DEMAE/issues/159)).
- `benchmark.arms` — one registry entry per arm, each declaring its encoder, its trainable part, its input convention and its normalization; the run verb dispatches on it.
- `benchmark.metrics` — `score(truth, filled, void, px) -> dict`, the graded metric set. Promoted from `prototypes/p123_metric_discrimination_proto.py`, whose ZT kernel is the one the 0.0006° divergence was measured on.
- `benchmark.results` — the results parquet schema, the run record, and the bootstrap.
- `benchmark.prereg` — `task1-prereg-bar.json` and its §6-phrase refusal, borrowing `dataset.validate`'s mechanism intact.
- `benchmark.report` — the printed table, the C4 rank block, the three figures.

**Where a synthetic void may be drawn.** §3.2's synthetic families are filtered to the test tiles that pass `benchmark.voids.eligible` — all-land, water flag clear — which drops 477 of the 5,000 and takes the synthetic half from 30,000 rows to 27,138. §3.1's test *draw* is unchanged at 5,000; this is a filter on where a void is placed, not on the split.

The reason is that a synthetic void is placed by geometry alone. `draw_from_seed` is a function of a seed and never opens the tile, so neither it nor `check` can see that the pixels underneath are Copernicus's painted ocean fill rather than terrain — and on the #150 draw, 400 of 30,000 instances held some ocean, 39 were mostly ocean and 8 were entirely ocean. ADR-0001 §3 masks the fill before differencing, so a void with no land under it leaves all five derivative metrics undefined, and one NaN takes a whole cell of the results table with it. The elevation columns are quieter but not worse: they stay finite and read ~0 m of error for interpolating ocean fill across ocean fill, which measured with A1 is 0.025 m against a population mean of 14.4 m and moves a cell mean by ~0.01 m. What those instances cost is meaning rather than rank — every arm is flattered by them about equally.

**The filter is on the tile and not on the placement**, and the alternative was measured before this was written. A land predicate inside the retry loop refuses 22.6% of the cells on the affected tiles — 114 of those 152 in the large bucket, because a 158 px void does not fit the land of a 26%-land tile at any placement — which would remove the large bucket from precisely the coastal tiles it keeps in the other two, and break the one-row-per-tile-per-bucket balance that makes bucket scores comparable across families. It would also end the property that a row is reproducible from its own seed. Dropping the tile keeps both, removes all 8 entirely-ocean and all 39 mostly-ocean instances, and leaves 11 carrying between 0.005% and 0.084% ocean and no NaN in any column. The loss is band-neutral (1,264/1,275/1,295/1,166 test tiles per ruggedness band becomes 1,127/1,127/1,158/1,111), and every (row, band) cell still clears R8's 100-instance floor by more than 11x.

It also removes a divergence that was already there: §3.3 has always transplanted onto `eligible()` hosts, so until this filter the two halves of one artifact were drawn over two different populations.

**The train mask bank is not filtered, and that is decided rather than inherited.** *(Settled 2026-09-14 — [#174](https://github.com/JStoschek/DEMAE/issues/174), the follow-up [#150](https://github.com/JStoschek/DEMAE/issues/150) left open.)* The bank draws K = 50 voids per head-train tile over §3.1's 20,000 whole, and it carries the same contamination the eval half did: of the committed 1,000,000 draws, **11,852 (1.19%)** hold some painted fill, **754 (0.075%)** are mostly fill and **117 (0.012%)** are entirely fill, those 117 over 72 tiles. Against the 400 (1.33%), 39 (0.130%) and 8 (0.027%) of 30,000 measured above on the unfiltered eval half, the bank is lower on all three and about half on the latter two. The head-train split being the cleaner of the two accounts for part of that — 588 of 20,000 tiles carry any fill, against 165 of 5,000 — but an 11% gap in tile rate does not explain a 2× gap in instance rate, and the decision does not turn on the remainder.

Three tile counts appear here and they are three different predicates, so they do not reconcile by arithmetic: **588** carry *any* painted fill (`land_frac < 1.0`); **492** fall under `voids.LAND_FRAC_MIN` (`land_frac < 0.999`), the threshold that actually rejects; and **1,157** is what `voids.eligible` rejects in total, being the wider test — under the threshold *or* water-flagged — which adds 942 water-flagged tiles overlapping the 492. Filtering as §3.2 does would drop all 1,157, the 96 tiles that carry fill without failing the threshold included.

Those pixels are not inert, which is the thing that looks true and is not. A void straddling a coastline has **land** in the boundary ring A1 interpolates from, so the fill laid over the ocean part is terrain while the truth there is a painted 0 m: measured per-pixel, painted fill carries a **13.74 m** learning target against the bank's own 15.85 m. A part-ocean draw really does ask the head to reproduce a constant, at very nearly full strength. Only an *entirely*-fill void is inert, its target 0.0036 m, and there are 117 of those.

What settles it is the magnitude, not the kind. Painted fill is **0.148%** of the bank's void pixels and **0.128%** of the elevation-loss mass those void pixels carry — the elevation half, since §4.1's loss is masked L1 in metres *plus* 0.1× a Sobel term and #174 measured the L1 term, which the three decimal orders of headroom here make sufficient. Against that, filtering the tile costs **1,157 of 20,000** head-train tiles — and, measured in the same unit as the 0.128%, **5.76%** of the bank's elevation-loss mass, so it discards **45× more signal than contamination**. Nor is it poor tiles being discarded, which is the reply this invites: the 1,157 carry **15.78 m** per void pixel against the kept tiles' **15.89 m**, so what goes is ordinary training signal and not marginal coastal flatland. Filtering would also take the label-efficiency rungs off 1k/5k/20k to 942/4,711/18,843: the lists are set-nested and the filter bites each at ~5.8%, so the rungs stay nested but stop being round. Filtering the *draw* keeps the tiles and the rungs but makes the bank a function of the corpus, which `draw_from_seed` is written not to be. And neither repair moves a scored number: every eval tile is already clean ground, so what these draws teach is a behaviour the results table never exercises — noise and spent capacity at roughly one part in 800, not a bias on anything reported. Set beside that, any change re-hashes the draw and invalidates the **training** of every arm that has run, not merely its scoring, because `launch run` trains before it scores and there is no score-from-checkpoint path.

**Committed inputs, and where the bank goes.** The tile lists, the eval mask list (~40k rows), `extractor_spec.json`, `task1-prereg-bar.json` and the dataset card are committed to git. The train mask bank is **1,000,000 RLE rows and 104 MB and cannot be**, on the same rule the corpus's shards follow: it is generated once by `freeze`, its md5 and generator config hash are committed in a sidecar, and `run` refuses a bank whose md5 does not match. This preserves the determinism contract — the mask sequence a run sees is still a committed input, its *hash* rather than its bytes — and it is the one place this spec resolves something the plan left implicit. State it in the dataset card rather than letting a reader infer that the bank is in the repository. (The ~740 MB this paragraph used to quote is the *uncompressed* RLE payload; the committed parquet is zstd and measures **104 MB** — [#151](https://github.com/JStoschek/DEMAE/issues/151). The rule is the corpus shards' rule, not a size threshold, so nothing here turns on which figure it is.)

**Arm registry.** A1 (classical fill — the `gdal_fillnodata`-class method in two variants: rasterio `fillnodata` and TPS. *Amended 2026-08-13 ([#158](https://github.com/JStoschek/DEMAE/issues/158)): this line read as three variants and describes two, since `rasterio.fill.fillnodata` is a binding of GDAL's `GDALFillNodata` — plan §1 carries the amendment*), A2 (DEMAE zero-shot), A3 (DEMAE fine-tuned), A4 (DEMAE frozen + head), A5 (TerraMind frozen + head), A6 (ImageNet-MAE frozen + head), A7 (UNet from scratch), A9 (tokenizer pass-through). A2/A3/A4 each split R5/R4, giving the eleven printed arm rows. A8 and A10 do not exist in the registry — they are out of scope and adding a disabled entry for either would put a ruled-out arm back on a surface someone reads.

**The head.** LayerNorm on patch tokens → 1×1 conv to 256 → four stages of [3×3 conv, GroupNorm, GELU, 2× bilinear upsample] at (256, 128, 64, 32), with the full-resolution void mask concatenated at each stage's input and a 1-channel residual output added to the A1 fill. **1.08M parameters at 384-d and 1.18M at 768-d** — §4.1's "~3M" is wrong and §7 says so; print the corrected figures. Loss is masked L1 on void pixels in metres plus 0.1× an L1 slope-consistency term on Sobel gradients inside the void. AdamW, lr 1e-3, wd 0.05, cosine to 0, 5% warmup, bf16, batch 128, 50 epochs on the 20k set, early stop on val RMSE. *Amended 2026-09-01 ([#159](https://github.com/JStoschek/DEMAE/issues/159)): "early stop" is implemented as **checkpoint selection** — the full cosine runs and the weights a cell keeps are its lowest-val epoch's. Truncating the schedule instead would need a patience this plan does not state, and would cut a cosine-to-0 curve off mid-decay: two recipes fighting, one of them invented by the build. Every epoch is checkpointed, so a later rule can be applied to the files rather than by re-training.

Two further readings recorded at the same time, both [#159](https://github.com/JStoschek/DEMAE/issues/159)'s:

* **"the full-resolution void mask concatenated at each stage's input"** names the mask that is *pooled*, not the resolution each stage sees. A stage is [conv, GroupNorm, GELU, upsample] in that order, so four stages from a 14×14 token grid take their inputs at 14, 28, 56 and 112 px and none at 224 — the alternative reading is not expressible by this paragraph's own stage order. What the phrase buys under the reading taken is that the mask is area-pooled from the 224 px void rather than arriving on the token grid, so a void finer than a 16 px patch is still visible to the first stage.
* **The tuning pass runs at 10 epochs, not 50.** A number the build chose; it decides only which grid point wins, and the 50 is untouched wherever a cell is scored. The grid itself is **the learning rate alone** — `slope_weight`, the loss's shape, the batch size and the epoch count are values this section *states*, and a grid over any of them would let a val RMSE re-decide a plan decision, which "Out of Scope" forbids.*

**Extractor interface.** `extract(raw_i16, valid_mask, *, arm) -> Features` where `Features` carries `output`, `intermediates` (twelve, ordered), and `cls` (DEMAE family only, `None` for TerraMind). Canonical layout `(N, 196, D)`, row-major. fp32 is the reference; compute dtype is a declared field per task; storage dtype is outside the contract. The spec file's fields and its four load-time checks are ADR-0012's, unchanged.

**Results parquet.** One row per (arm, init, size, seed, family, bucket, band, tile_id, instance) carrying every metric in the registered set — the six headline columns and the four appendix ones — plus the eroded-mask slope, the instance's void area and equivalent diameter, and the mask's RLE hash. **Computed and printed are different questions**: nothing that collapses an axis for print discards a number, so `report` is a pure function of this file and re-rendering the table never re-runs an arm. The run record beside it carries the config hash, the extractor spec md5, the mask bank md5, the tile-list md5s, the git SHA, and each arm's total and trainable parameter counts.

So no source ever decided against printing the gap; the plan multiplied by five and dropped the derived column. Plan §5's four copies, R1, R5 and this spec were amended together, before any arm ran.

Second, **the bank's own 1M / K = 50 figures were never stale** — the bank is 20,000 head-train tiles times K whatever the pass count does, so what moved was only the ratio it is quoted against (**31.2×**, not 34.4×). An A6-vs-A6-S delta would confound capacity with trainer and schedule, which is not what §2.3 asked for. A4-S stands alone; the ViT-S appendix is one cell. No registered rule moves — R5 fixes the *printed* table and both ViT-S cells are `printed=False` — so this needed no ADR-0013 amendment. This one was found by the build rather than flagged in advance, which is the "When the build finds the plan wrong" disposition working as written.

4. **A4-S's encoder had no file, and no pin.** **Settled 2026-09-16 — exported from R1** ([#164](https://github.com/JStoschek/DEMAE/issues/164)). §2.3 registered the ViT-S appendix cell and `benchmark.arms` registered its `demae-vits` encoder, but `paths.demae_vits_checkpoint` defaulted to `None` and `checkpoint_md5` was `None` beside it, with the registry's own comment giving the reason: no §2.3 ViT-S run had been released. Both halves had to move, and the **second** is the one that made the cell unrunnable rather than merely unmounted — `benchmark.extract.Extractor._checked_path` refuses an unpinned encoder outright (ADR-0012 §7.1), so A4-S would have failed at load on a box that had mounted the right weights. That is [#159](https://github.com/JStoschek/DEMAE/issues/159)'s A6 finding a second time, at a different provenance, and it is why the "every registered encoder publishes an md5" test now asserts **no exception** rather than one.

   The weights are R1's — Phase 1's ViT-S/16 scratch baseline, the recipe R5 was later trained under at 4x the parameters. The pretraining plan's §14 scoped the releases to the two ViT-B arms and said of R1–R3 that `python -m pretrain.release` "packages any of them in minutes if a consumer ever appears"; §2.3's appendix cell is that consumer, so this is the plan's own escape hatch being used rather than a scope change. The export is **not** a §14 release and must not be published as one: it carries no `curves.csv`, so it is a §14-incomplete bundle, and it lives at `.release-work/export-R1-vits/` rather than `release-R1/` to keep that legible. Provenance is a two-link chain and both links are checkable — `s3://demae-checkpoints/r1/checkpoint_e0400_s000092400_milestone.pt` (md5 `a1be572edb001ed9f871197b1d8edddf`, a *milestone*, which is why it survived the 2026-09-15 retention prune), and the manifest beside `encoder.pt` naming it as `source_checkpoint`.

5. **§2.3's shape for the appendix cell was declared and unenforced.** **Settled 2026-09-16 — refused at `resolve`** ([#164](https://github.com/JStoschek/DEMAE/issues/164)). `head.appendix_seeds = 1` had been in the config since §4.1 was written with **nothing reading it**. So `run --arm A4-S --seed 1` was an ordinary command, and a second observation landing in the parquet is a bracket any reader could take whatever the report chose to print. `benchmark.arms.Arm.single_observation` now declares the fact where the arm is named and `benchmark.launch._checked_cell` refuses on it, reading the *number* from `appendix_seeds` so the recipe's knob is finally load-bearing. The refusal is in `resolve` rather than in `run` for §4.1's two recipe refusals' reason: `--dry-run` returns before the verb, so a check inside `run` would print a second observation as though the plan had asked for one. The field is deliberately **not** a reading of `printed` — `A5-BICUBIC` is an appendix cell carrying three seeds, and A9's two rows train nothing at all, so `printed` and "how many observations" are two questions. The refusal is a **guardrail rather than a boundary**: `appendix_seeds` is not in `TUNED_FIELDS` — `Head.tuned` excludes the three seed counts deliberately, so that a smoke run at `head.seeds=1` is not read as a thumb on the scale — so `--set head.appendix_seeds=3` does open seed 1, and `tune.assert_frozen` will not refuse it. That is the intended shape: the refusal stops the *accidental* second observation, and moving `appendix_seeds` is meant to be the deliberate act. What keeps the deliberate act from being a silent one is that `appendix_seeds` reaches `config_hash`, which is a column on every parquet row and is in the run record.

   The **size** half of §2.3's sentence is refused by the same function, because it is the same sentence: the cell is one observation *at 20k*. §7 prices the label-efficiency sweep at three cells by two seeds and annotates it "R4 and ViT-S are both out of the sweep (§2.3)", and §4.5 orders the appendix cell with the 20k block. So `run --arm A4-S --size 5k` was a row nothing budgeted and no §0 claim reads, and it is now refused by name. The headline size is read from `LABEL_EFFICIENCY_SIZES[-1]` rather than typed, on `report.HEADLINE_SIZE`'s rule.

**What is not re-decided here.** The size buckets and their 158 px top, the +0.15° seam threshold, the four bootstrap pairs, R5 as the headline, the 20-epoch TerraMind citation, the metric grading, the real family's R4-only stratification, and the twelve registered rules are all settled records. If the build finds one wrong, it surfaces it as an amendment against the plan and ADR-0013 — it does not route around it.

## Testing Decisions

**What makes a good test here.** The suite is ~1,600 tests and is the gate before every push; there is no typechecker, so pytest is the only gate. A good test drives the shipping entry point far enough to see an artifact, and asserts external behaviour: a file exists with the rows it should have, a table prints the columns it is allowed to print, a wrong input is refused. This repo has a named failure — *the composition* — for the shape where every piece is tested and nothing calls them together, and the standing defence is a test that drives `main(argv)` rather than one that drives each piece.

**Seam 1 — `benchmark.launch.main(argv)`, the primary.** Nearly every behaviour test attaches here, against a tiny fixture corpus built by `tests/conftest.py`'s existing `build_corpus` (a test geocell, a val COG, controllable geography) and a stub encoder. Prior art is `tests/test_pretrain_launch.py`, and the three tests ADR-0009 named — `test_the_shipping_command_writes_a_checkpoint`, `..._opens_a_run_and_logs_the_epoch_panel`, `..._carries_the_recipe_the_run_was_launched_with` — are the template. The benchmark's equivalents: the shipping command writes rows to the results parquet; the run record carries the recipe, the extractor spec md5 and the mask bank md5 the run was launched with; `report` renders from the parquet without re-running an arm; a typo'd override stops before the corpus is touched; `--dry-run` assembles everything and writes nothing; `freeze` is idempotent and refuses a changed artifact; a mask bank whose md5 has moved is refused rather than read.

**Seam 2 — `benchmark.extract`, mandated rather than chosen.** A second consumer (Task 2) re-reads this contract, and ADR-0012 Decision 4 explicitly requires Task 1 to test the intermediates path *even though no Task 1 arm reads it* — shapes, ordering, count, and the layer-12-versus-`output` relation on both sides. No launch-level behaviour exercises that path, so the test cannot attach at seam 1. Also here: the spec refuses a wrong checkpoint md5; refuses TerraMind constants that resolve by name to a value other than `670.665 / 951.272`; refuses a declared layer count that does not match the model loaded; recomputed statistics reproduce the manifest's stored `mean`/`std` within the measured bound over a tile sample; and a pre-normalized tensor is not a thing the interface accepts.

**Seam 3 — `benchmark.metrics.score(...)`, for the numeric identities.** The claims that are equalities against another module or against a fixed constant, which read badly through a CLI: ZT slope equals `dataset.metrics.slope_deg` to 0.0006° over a tile sample; NMAD equals `1.4826 · median|Δh − m|`; the seam gap equals full-mask minus eroded-mask slope RMSE by construction; +0.15° is read from `task1-prereg-bar.json` rather than typed; aspect error is circular; a metric requested outside the **registered** set raises rather than being computed. **Registered, not graded** ([#146](https://github.com/JStoschek/DEMAE/issues/146)): the gate reads R1's roster — the five graded headline columns, the derived seam gap, and the four appendix ones — because the seam gap is computed and parqueted while sitting outside the ten p123 graded, so a gate keyed on the *graded* set would raise on the very metric the sentence above requires `score` to return. R1's roster is the single list this gate reads from; the seam gap is not carved out by name, since a second home for the metric roster is what produced #146 in the first place. §8's **golden-tile fixture** — a committed tile with a known void and a hand-checked fill — lives here and is also driven through seam 1 as A1, so the same numbers are asserted at both altitudes.

**Modules tested through seam 1 rather than directly:** `benchmark.tiles` (assert the committed lists' composition and that a contaminated split is refused), `benchmark.masks` (assert the constraint checks fire over a draw sample — zero cap violations, zero interiority violations, buckets by equivalent diameter — and that the bank's K = 50 rows per tile differ), `benchmark.voids` (assert the predicate yields a non-empty mask, that the `num == 0` rule yields an empty one and is therefore refused, that bands come from GLO-30 and not from the SRTM surround, and that `|lat| ≥ 50` is rejected), `benchmark.report` (assert the printed table's shape is exactly R5's, that an appendix metric never reaches print, that exactly four pairs carry a CI mark, and that a sub-100-instance cell prints a count and no metric), `benchmark.prereg` (assert the bar refuses to load when a registered §6 phrase is edited out of the plan — the mechanism `dataset.validate` already ships).

**Prior art to follow:** `tests/test_pretrain_launch.py` for entry-point tests, `tests/test_validate.py` for the bar-phrase refusal, `tests/test_masks.py` and `tests/test_metrics.py` for numeric-identity style, `tests/test_p127_fetch_srtm_voids.py` for testing a fetch path without a network, and `tests/conftest.py`'s `build_corpus` for the fixture corpus. Every write goes to `tmp_path`; nothing shares mutable state, because the suite runs sharded under `pytest-xdist`.

**What is not tested:** GPU throughput, and any claim about the *magnitude* of a result. The benchmark's job is to produce numbers; asserting a particular number in a test would pre-empt the very claims the pre-registration exists to leave open.

## Out of Scope

- **A8 (Diff-DEM cross-eval) and A10 (GeomorPM cross-eval).** Both ruled out and closed off in #128; §0 now carries the strong form — incomparable, and we looked. Not to be added as disabled registry entries.
- **The secondary 10 m TerraMind-native regime.** Reaffirmed out of scope in #139 on stronger evidence than the ruling had. What stands in its place is §2.2's measured, symmetric caveat, already landed.
- **Task 2 (landform classification) and the cross-cutting representation study.** Own plan doc, own map. This build fixes the extractor contract Task 2 inherits and nothing else; `task2-landform-plan.md`'s three stale feature-cache references are Task 2's map to fix, not this spec's.
- **Re-opening any Phase-0 or Phase-1 decision** — the tiling, the strata, the split, per-tile normalization, the frozen release recipe. Moving the primary regime to 256 px is specifically refused, since it would retile the corpus.
- **Amending the metric set, the bucket boundaries, the seam threshold or the table shape** on the basis of a result. Those are registered rules; an amendment needs a ticket and an ADR amendment, in that order.
- **A feature cache.** Priced at a $0.50 saving against a design constraint it breaks; the encoder runs inline.
- **Spot-instance or resume machinery.** §7's total is 5.09 GPU-hours with a **58-minute** longest job (one A7 seed, measured — [#175](https://github.com/JStoschek/DEMAE/issues/175); the 46 minutes quoted here before was A7's whole 3-seed line at a primitive that measured 4.5x low, not a job). Heads checkpoint per epoch like everything else in this repo and that is the whole of it.

## Further Notes

**The budget is not the constraint and should stop being treated as one.** $3.00 of GPU against a $25 target, on the project's own laptop for the CPU hours *(it read $0.99 before [#163](https://github.com/JStoschek/DEMAE/issues/163) priced A9 at all, $2.17 once [#175](https://github.com/JStoschek/DEMAE/issues/175) measured A7 at 4.5x its estimate, and moves again now that [#168](https://github.com/JStoschek/DEMAE/issues/168) has run A9 and found its transferred price 7.6x low)*. The real budget is attention and wall-clock: the three largest lines are now comparable — 2.0–5.2 CPU-hours of eval scoring against A7's measured 3.44 GPU-hours and A9's measured 2.37 — and the combinatorics of arms × families × buckets × bands × seeds produce a table nobody can read long before they produce a bill anyone can feel. Every convnet line priced off the transformer-anchored ratio has now come in high when someone ran it, twice; **the head primitive is the last one still transferred** — see §7.

**Everything needed is already on disk.** The 47 GB `corpus_500k` shards, the committed split, the R4 and R5 release encoders under `.release-work/`, the 24 fetched SRTMGL1N granules under `data/srtm_voids/`, and the p135 component catalog. The laptop has MPS, so non-CPU work reproduces locally and "needs a rented GPU" is usually false. A *new* DAAC would still need a human's consent click; nothing here does.

**Pin `diffusers` in the benchmark's own environment**, at the version the TerraMind path is verified on (terratorch 1.2.10 / diffusers 0.39.0 in p118). terratorch declares a bare `diffusers`, so nothing is pinned and a future release can break the tokenizer import with no lockfile signal.

**Order of operations** is §4.5's, with §7's pass breakdown as the authority on cell and seed counts — §4.5 orders them and has drifted from them once already. Freeze, then A1 plus the norm-inversion and golden-tile gates, then head tuning on A6/val, then the four primary frozen cells at three seeds plus A7 at three and the ViT-S cell at one, then the 1k/5k sweep, then A3, then A2 and A9.

**When the build finds the plan wrong.** It will; this map found a stale parameter outliving its governing ruling three separate times, and ten sites still carrying an arm ruled out at charting. The disposition is the one the map used throughout: amend the section in flight, record it against the ticket, and if it touches a registered rule, amend ADR-0013 in the same change. There is no big-bang rewrite.
